# 一、项目概述

## 1.1 一句话

我们用自研的 Agent Harness（零第三方编排框架）把「原始投研材料 → 可信事实库 →
估值模型 → 报告核查」串成一条闭环流水线，其中每一个数字都能回溯到原文的哪一页、
哪一行、哪一个表格单元格，每一次运行都能逐字节复现。

## 1.2 我们要解决的问题

金融投研场景里，AI 最容易出的问题不是"不会算"，而是看起来算对了：

| 现象 | 典型后果 |
|---|---|
| 模型读出 `583,965.66` 时把折行的 `583,96⏎5.66` 读成 `58,396` | 错一位数量级，报告里毫无痕迹 |
| 行标签写着「单位：万元」而正文按元处理 | 现金放大 100 倍，DCF 每股价值从 ¥12 变成 ¥124 |
| 用净利润冒充 EBIT | 自由现金流被系统性高估，估值偏高却"逻辑自洽" |
| 报告引用的数字在原始材料里根本不存在 | 幻觉入文，读者无从核对 |

这些错误的共同点是：程序不报错、阶段状态是 success、报告看起来很正常。
本项目的全部设计都围绕一件事：让这类错误无法静默通过。

## 1.3 我们的答案（三条硬机制）

1. 无锚点不入库：任何一条数字必须有原文锚点（页码 / 行号 / bbox）+ 引文回读校验，
   否则不进事实库。
2. LLM 只负责"提出"和"解释"，代码负责"确定"和"证明"：模型读数必须由
   *它无法影响的*几何/算术事实背书，才允许改写程序读数。
3. 过程全量留痕、产物逐字节可复现：`trace.jsonl` 逐条记录文件访问、工具调用、
   模型调用、断言、逐页路由与阶段；`replay --strict` 离线重跑并逐字节比对。

# 二、赛题理解与选题说明

## 2.1 赛题要求我们做什么

竞赛以「金融投研智能体构建」为主题，要求在受控数据环境中完成
信息检索、数据处理、逻辑核验、量化计算和报告生成，重点考察
金融数据的准确处理能力、复杂任务的组织执行能力、
分析结论的准确性和专业性，以及运行过程的可验证、可追溯和可复现程度。

评分维度共七项：任务完成度、数据与计算准确性、分析逻辑严密性、
证据支撑充分性、结果稳定性、方案创新性、实际应用价值，并结合现场展示与答辩。

## 2.2 我们选择：选题 1 / 4 / 5

| 选题 | 内容 | 重点考察 |
|---|---|---|
| 选题 1 | 数据结构化提取 | 从非标公告、扫描文件、复杂表格中提取质押/中标/股权变动字段；字段完整性、格式规范性、表格解析准确性、结果一致性 |
| 选题 4 | 自动化估值建模 | 依据财务数据、经营假设与可比公司，建立 DCF 或相对估值模型，给出估值区间与敏感性分析 |
| 选题 5 | 研究报告纠错核查 | 核查草稿中的收入、利润、估值倍数、单位、统计口径与引用，识别错误并提出修改意见；准确率、覆盖率、误报控制、来源定位 |

## 2.3 为什么是这三个：它们不是三个功能，而是一条质量链

```
受控材料（公告 / 年报 / 扫描件）
      │
      ▼  三层解析引擎（文本层 → OCR → 多模态裁判）
┌──────────────────────────────────────────┐
│  R1 事实库 Facts                          │   ← 唯一数字真源
│  每条数字带：原文锚点 + 置信度 + 来源层     │
└──────────────────────────────────────────┘
      │                    │
      ▼                    ▼
┌──────────────┐   ┌──────────────────┐
│ R4 估值建模   │   │ R5 报告核查        │
│ 事实→假设→DCF │   │ 数字→反查事实库    │
│ →区间→敏感性  │   │ →五类错误比对      │
└──────────────┘   └──────────────────┘
```

关键设计：R4 与 R5 只消费事实库，不重复解析文档。
三个选题共用同一个数字真源，因此「事实库准不准」是一个可以被单独检验的问题 ——
这比做三个互不相干的功能更能体现任务的组织执行能力。

# 三、系统方案

## 3.1 总体架构

```
agent/                    ★ 自研 Harness —— 完全领域无关，可驱动任何任务
├── runtime/    loop.py       两级调度：宏观 Plan DAG + 微观有界 Agent Loop
│               budget.py     四道预算闸门（步数/token/时长/成本）
├── model/      gateway.py    模型网关：多角色、缓存、记账、结构化输出自我修复
│               cache.py      响应缓存 —— replay 与成本控制的基础
│               providers/    openai_compat（DeepSeek/Qwen/GLM/vLLM）+ mock
├── tools/      registry.py   工具注册表（副作用/确定性/成本声明）
│               fsguard.py    文件系统守卫（受控数据环境的执行者）
├── prompts/    registry.py   提示词注册表（版本 + SHA256 指纹）
├── skills/     registry.py   技能注册表（加载 SKILL.md 并校验绑定真实存在）
├── mcp/        client.py     MCP 协议客户端（JSON-RPC 2.0 over stdio，自研）
├── validate/   五道校验闸门（单位归一化 / quote 回读 / 勾稽断言 / 契约 / 数值）
├── evidence/   models.py ★ 全局数据契约（单一真源）  store.py 证据库 + 事实账本
└── trace/      tracer.py 全量事件追踪（JSONL）  replay.py 复现校验

domain/                   业务知识（提示词 / 技能 / 财务与文档工具）
pipelines/                r1_extract · r4_valuation · r5_audit · full
web/                      演示台（FastAPI + Jinja2 服务端渲染，无构建链、无 CDN）
```

一条命令即可复现全流程，这是评审进入本作品的方式：

```bash
python tools/reproduce_all.py     # 12 步，全部零依赖（不需 API Key / 不需联网）
```

最简使用方式（Web 一键）：把要分析的 PDF 放进 `inbox/raw/`，
浏览器打开 `/analyze`，勾选费用确认后点「开始分析」——
系统用真实模型跑完整的 R1→R4→R5，页面上实时显示 11 个阶段的进度与运行日志，
跑完后结果就在 `/library` `/facts` `/valuation` `/audit` 等页面里
（与命令行 `agent run full` 的产物完全同源）。

另有**控制台** `python -m web.panel --run <run_id>`（一页四标签：运行 / R1 / R4 / R5，
切标签不跳页）。它的右侧常驻一栏**模型与工具的原始记录**：模型收到的完整提示词、
它答的原文、工具收到的入参与返回的原文，一条一条往下流，运行中每 2 秒续读。
这一栏读的是 `agent_log.jsonl`，与 `trace.jsonl`（按契约只记载荷哈希）是两路数据 ——
看过程要的是前者。`--mock` 的离线自检 run 在这一栏里与真实 run 无从分辨，
所以页眉会挂出「离线自检」，运行中的 run 则从 `checkpoint.json` 判读。

## 3.2 R1 数据结构化提取：三层解析引擎 + 逐页确定性路由

第一层 文本层直取：有文本层的页面直接取字，零成本、零幻觉。

第二层 OCR：无文本层的扫描件走本机 OCR（纯 CPU，无需 GPU），
配合扫描件预处理链（灰度 → 分辨率归一 → 纠偏 → 去噪）。

第三层 多模态裁判：关键字段交由视觉模型裁决，但模型不能单独决定结果 ——
它的每一次改写都必须由它无法影响的几何事实背书：

* 表格先按单元格 x 区间重叠重建列结构（不看列号，改看坐标），
  实测 730 / 987 张真实表格的列结构被重建；
* 单元格裁决时，程序读数与模型读数并列，只有当模型读数与网格几何
  （折行位置、数字连续性、量纲）一致时才采纳，且必须通过 quote 回读；
* 没有原文锚点的数值一律不入库。

逐页路由是这套设计的关键：每一页走哪条通道是确定性判据算出来的
（字符数、乱码率、文本覆盖率、线段密度），并逐页写入 `trace.jsonl` ——
评审可以逐页追问「为什么这一页走 OCR」。

## 3.3 R4 自动化估值建模：事实 → 假设 → 模型 → 区间 → 敏感性

* DCF（FCFF）：显式预测期 + 永续增长；折现率由 CAPM 逐项推导
  （无风险利率取自带来源 URL 与日期的市场利率缓存）。
* 相对估值：可比公司倍数法，真实同业快照（含抓取时间戳与来源），
  有意剔除目标公司自身。
* 估值区间：取两个方法结果的并集极值（而非平均）—— 平均会掩盖模型分歧。
* 敏感性：双因素网格热力图 + 单因素龙卷风图 + 区间图。
* 勾稽断言：A1–A6 六类会计恒等式独立重算（不是把模型的中间量拿来比对，
  那叫自证不叫校验），任一 FAIL 即阻断报告输出。

假设的三种属性在报告里显式标注：绿色代表事实，齿轮图标代表一致性调整，蓝色代表观点。
每条假设可回溯到具体页、具体表格单元格。

## 3.4 R5 研究报告纠错核查：五类错误 + 零误报优先

| 类别 | 检查内容 |
|---|---|
| E1 数值 | 草稿中的数字能否在事实库中找到来源（无来源即报错） |
| E2 单位 | 量纲族隔离 + 单位归一化（万元/亿元/元） |
| E3 口径 | 合并/母公司、归母/扣非/全部净利润、时点/期间 |
| E4 引用 | 引文是否真实存在于原始材料 |
| E5 倍数 | 静态/TTM/前瞻口径隔离，防止倍数张冠李戴 |

误报控制是硬约束：完全正确的草稿必须零发现
（`test_no_false_positives_on_clean_draft` 守着这条线）；
评测黄金集里专门放入 11 条"陷阱项"（看起来像错、其实是对的），
用来防止"宁可错杀"的规则漂移。每条发现都给出原文锚点 + 修订值 + 批注版草稿。

## 3.5 可验证 / 可追溯 / 可复现是怎么做到的

| 赛题要求 | 实现 |
|---|---|
| 数据来源可核验 | 事实库每条数字带原文锚点（页/行/bbox）+ 引文 + 置信度 + 来源层 |
| 执行过程可追溯 | `trace.jsonl` 记录**文件访问**、工具调用、模型调用、断言、逐页路由、阶段与错误；`agent audit` 生成人类可读版 |
| 运行结果可复现 | 响应缓存按内容哈希；thinking 关闭（官方文档确认思考模式下 `temperature` 不生效）；`replay --strict` 离线逐字节比对 |
| 受控数据环境 | 默认禁止出网；`--offline` 下缓存未命中直接报错，不会悄悄联网。读写分离由运行时闸门强制（`FileGuard` 挂在 `RunContext.guard()` 上，越界抛 `SandboxViolation`）；产物侧另强制禁止绝对路径 |

# 四、关键创新点

## 4.1 自研 Agent Harness：零第三方编排框架

评测框架本身不是黑盒 —— 编排、工具注册、提示词版本、技能绑定、MCP 客户端、
追踪与复现全部自研，因此"过程可追溯"不是某个框架的日志开关，
而是这套系统的结构性属性。赛题点名的核心模块（编排框架 / Tool / Prompt /
Skill / MCP / 数据处理 / 日志）全部可直接点开查看，并有体检守住文档与代码一致：

```bash
python -m agent.cli tools            # 17 个工具 / 7 个模块（含副作用与确定性声明）
python -m agent.cli prompts          # 5 个提示词（版本 + SHA256 指纹）
python -m agent.cli skills           # 3 个技能（校验绑定的工具/提示词真实存在）
python -m agent.cli mcp --self-test  # MCP：真实子进程，握手/发现/调用/错误路径
```

## 4.2 几何佐证驱动的单元格级视觉裁决

模型改写程序读数时，必须由模型无法影响的几何事实背书
（折行位置、数字连续性、量纲一致性、网格对齐），并且裁图作为物证随产物落盘 ——
评审点开 `pages/cells/<doc_id>/` 就能看到"模型当时看到的那张图"。

> 没有那张图，"视觉裁决"就只是一句自述。

## 4.3 三态勾稽断言：未校验 ≠ 失败

A1–A6 断言有三种结果：通过（独立重算一致）、失败（校验过且不一致）、
未校验（缺辅助明细，本次无法独立重算）。三者在报告里分开计数 ——
把"未校验"算成"失败"会虚报问题，把"失败"洗成"未校验"会掩盖问题。
（这条区分由一个正例、一个反例两条测试钉住。）

## 4.4 一条工程纪律：判据的杀伤半径必须在启用之前量出来

修一个 bug 的规则本身常常会制造更多错误。本项目把这条做成流程：
任何"改期间/改列结构"的新规则，启用前先用量测工具在真实语料上量出
命中率与附带损害。

这条纪律有直接的代价记录：有一轮守卫规则"写完再量"，把 `needs_review`
从 159 条推到 529 条、可用净资产从 16 条掉到 0 条，只能整条回退；
另一轮先写量测工具，在 987 张真实表上两次否掉自己的判据，
第三次才收敛到 4/987 张、零误报。

# 五、验证与实测数据

## 5.1 验证方法：十八轮真实数据验证

全部结论建立在真实公开材料上，不使用合成数据作为证据：

| 语料 | 规模 | 来源 |
|---|---|---|
| 真实年报 | 4 份 / 943 页（中国石油 2024、2025；湖南发展 2025；湖南白银 2025） | 巨潮资讯网 |
| 真实公告 | 77 份（质押 13 / 中标 12 / 股权变动 19 / 利润分配 11 / 对外担保 22，共 923 页） | 巨潮资讯网 |
| 其中无文本层扫描件 | 106 页 / 14 份（已渲染页面人工核对，确认均为纯文字扫描件） | 同上 |

> 说明（一）：这 77 份公告已于 2026-09-27 跑通，产物在
> `runs/ann77-20260927`（7/7 阶段，765 条事实，47/77 份文件有命中，
> 即 36/62 份不同文档）。
> 赛题点名的三类字段都有实测条数：质押 31 / 中标 30 / 股权变动 46 = 107 条
> （毛数）。但 107 是下界：视觉通道 400 次预算用尽（84 次整页扫描 +
> 316 格裁决），闸门用尽后 `judge.py` 静默 `break` 掉后面所有表格的裁决，
> 且不留任何记录；另有 382 条候选被「单位缺失」闸门否决。材料里到底有
> 多少个该抽的字段没有金标准，需人工逐页点数才能给出分母。
>
> 说明（二）：「77 份」里有 15 对是同一份文档。 `doc_id` 按内容哈希
> 生成，语料里 15 对文件的 sha256 完全相同（同一份公告重复抓取，只有文件名
> 里的 `h` 序号不同）—— 所以 77 份文件只对应 62 份不同文档
> （923 页对应 681 个不同页）。任何按 `doc_id` 汇总的统计都会把这 15 对
> 重复计一次：我们在演示台 `/library` 上就是因为这个出现了
> 「卡片 158 / 明细列 270」同页矛盾，已修（明细列改数每份文件自己的路由，
> 重复行加「重复 ×N」标记）。这批重复文件我们没有删 ——
> ingest 去重属于 `pipelines/` 的计算逻辑，按约定不动；
> 且删除语料会改变已冻结 run 的输入指纹。是否清理由你决定。
>
> 说明（三）：此处曾写「296 份」，那是把当时 `agent/sample/_scratch/` 下
> 219 份无分类标签的抓取临时件一并算进来的历史规模。那些临时件**不在本仓、
> 也从不随源码包提交**（打包器按 `_` 前缀规则排除 `_` 开头的目录），
> 所以今天在仓库里跑 `--data agent/sample` 与在交付包里跑，ingest 的都是
> **77 份**这一档，输入集一致；`runs/ann77-20260927` 记录的 `data_dir`
> 正是 `agent/sample`，在仓库里可以直接按它复现。

每一轮验证都记录：假设 → 命令 → 实测输出 → 结论 → 被推翻的中间结论，
共十八轮，全部留档在 `docs/VALIDATION_ROUND*.md`，索引见 `docs/VALIDATION_INDEX.md`。

# 十、已知限制

1. 阶段间仍有内存态（未根治）：跳过某些阶段续跑会丢失只存在于内存的状态；
   已加"从产物水化"与"空库硬失败"两道保险，但结构性修法未做。
2. 报表归属跨页错标：整页高的续表会让标题落在表内；
   试过按文档顺序修，被实测否决（口径与期间互相纠缠）。
3. 多年摘要表的期间仍可能错位：值可用、期间需人工核对。
4. 3 张分部表未对齐：系统返回"不猜"，那 3 张表的分部合计取不到。
5. EV/EBITDA 缺失：现金与有息负债没有可靠的结构化公开来源，相对估值少一个倍数。
6. 抽取结果对单格模型读数敏感：冷启动结果不完全可预期。
7. 续跑重跑阶段会留孤儿产物：操作规避是换新 run 名重跑。
8. DCF 与相对估值仍有约 7% 差距，来源已量化
   （CAPM 算出的 WACC 低于市场隐含要求回报率），
   且不用市价反向校准 WACC —— 那会让 DCF 退化成把市价重算一遍。

> 完整的 8 条未解决问题、每条根因与量化影响见 `docs/VALIDATION_INDEX.md` 第五节
> 与 `README.md` 的「已知限制」。
