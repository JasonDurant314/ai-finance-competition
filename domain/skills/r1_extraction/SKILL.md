## 考察点与对策

| 官方考察点 | 我们的对策 |
|---|---|
| 字段提取**完整性** | 别名表覆盖每个指标的多种写法；`data/golden/` 提供标注集量化覆盖率 |
| **格式规范性** | 所有数值归一化到「元/股/%/元每股/倍」，经 `agent/validate/numeric.py` 统一换算 |
| **表格解析准确性** | 三引擎表决（文本层聚类 / 几何线段 / VLM 读图）+ **算术校验**（合计≠分项和即定位到具体单元格） |
| **结果一致性** | 事实库是唯一数字真源；R4/R5 只消费它，不重新解析文档 |

## 执行流程

```
1. 登记      计算 SHA256 → doc_id；记录输入文件哈希
2. 逐页预扫描 字符数 / 乱码率 / 文本覆盖率 / 图像覆盖率 / 线段密度
3. 路由决策  按 configs/routing.yaml 判定 A/B/C/D/E 五类路径
4. 三通道解析
   ├─ 通道 1 文本层直取（基础置信 0.95）
   ├─ 通道 2 OCR + 规则校验（0.80）
   └─ 通道 3 VLM 裁判（仅在冲突/扫描页/表格页/关键字段触发）
5. 交叉验证  通道比对 → 量纲校验 → 算术校验 → quote 回读
6. 构建事实库 三重硬闸门过滤后入库
7. 导出      JSON / Excel / 溯源 HTML
```

## 关键约束

### 无锚点不入库
每条 `Fact` 必须携带至少一个 `evidence_span_id`，
且该锚点的 `quote` 必须能回到页面原文中匹配成功（精确或模糊 ≥ 0.86）。

### 无单位不入库
单位缺失时**拒收**而非猜测。猜错单位的代价（在下游制造误报）
远大于缺失的代价（降低覆盖率且会显式声明）。

### LLM 不产数字
模型只输出 `raw_text`（页面原样字符串），
所有换算、舍入、汇总由 `Decimal` 精确运算完成。

## 常见陷阱（实测踩过）

1. **「占公司总股本比例」中的「总股本」不是总股本**
   → 匹配必须以数值为中心，且做量纲族校验

2. **「归母净利润」与「净利润」互相抢值**
   → 按别名长度降序做全局区间仲裁，长别名先声明

3. **`get_text("dict")` 的顺序 ≠ 阅读顺序**
   → 权威页面文本一律用 `get_text("text")`

4. **续表页不重复印年份**
   → 需文档级期间识别作为页级回退

5. **`text_coverage` 不能判断页面有无文字**
   → 用 `char_count`；覆盖率阈值需按正常排版（0.2–0.4）设定
