## 核心方法论

> **不用「让大模型通读找错」，而是用事实库做确定性比对。**

```
R1 事实库（数字真源）
        ↓
报告草稿 → 抽取数值主张 → 反查事实库 → 独立重算 → 比对 → 分级输出
```

这条路径的优势：
- **准确率不依赖模型当时的状态** —— 同输入必然同输出
- **每条结论都能给出正确值 + 来源 + 算式** —— 可执行、可复核
- **无法确定性判定时显式降级为"疑似"** —— 不猜

## 五类错误

| 类型 | 官方考察点 | 判定方式 | 典型错误 |
|---|---|---|---|
| **E1** 单位 | 单位 | 换算到统一量纲后比对；量级差 10⁴/10⁸ 即为强证据 | 万元↔亿元、%↔小数 |
| **E2** 估值倍数 | 估值倍数 | 从事实库独立重算倍数 | 分母用扣非却称归母；用流通市值算 PE；EV 未扣净债 |
| **E3** 统计口径 | 统计口径 | 每条事实带 `caliber` 标签，与报告表述比对 | 合并 vs 母公司；归母 vs 扣非；单季 vs 累计 |
| **E4** 引用 | 引用 | 数字反查事实库 | 无来源；数值与唯一可查来源显著不符 |
| **E5** 算术 | 收入、利润、单位、统计口径、引用 | 由事实库两期数据独立重算 | 同比算错；占比算错 |

## 三级严重度

| 级别 | 定义 | 处置 |
|---|---|---|
| 🔴 `confirmed` | 与事实库硬冲突 / 算术错误。**必须有 `source_evidence`** | 必改，给出正确值 |
| 🟡 `suspected` | 口径不明 / 需要人工判断 | 建议核实，可给两种解释 |
| 🔵 `advisory` | 规范性问题（缺单位、缺报告期标注） | 可选改进 |

> `Finding` 的模型契约强制要求：**`CONFIRMED` 级发现必须携带来源证据**，
> 否则构造失败。没有来源的"确认错误"本质上是猜测。

## 误报控制 —— 本技能最重要的部分

核查系统最大的失败模式不是漏报，而是**误报**。
以下四处防线都是实测踩坑后建立的：

### 1. 派生指标豁免
增速、占比、比率是**算出来的**，事实库里没有同名记录。
E4 必须跳过它们；其正确性由 E5 独立重算负责。

### 2. 口径判定防陷阱
「归属于母公司股东的净利润」中的"母公司"**不等于**母公司报表口径。
若误判，每条归母指标都会被报成口径错误。
`detect_statement_scope()` 对含"母公司"但不属明确口径表述的情况**一律不判定**。

### 3. 同位置优先级抑制
同一字符区间若已有 E1/E5 这类确定性数值错误，
不再重复报 E3/E4 —— 后者往往是前者的副作用。
重复报错会虚增问题条数并直接拉低精确率。

### 4. 量纲族隔离
金额 / 股数 / 比率 / 每股 四族之间**禁止跨族比对**。
否则「7.92%」会被拿去和「2,456,000,000 元」比较并得出荒谬结论。
反过来，草稿写"万元"、事实库存"元"时必须**先归一化**，
否则正确的数字会被判成"无来源"。

## 评测

`data/golden/<draft_id>.labels.json` 提供人工标注：

```json
[
  {"error_id": "G-001", "type": "E1_unit", "char_range": [1024, 1067],
   "is_real_error": true, "note": "单位错误"},
  {"error_id": "T-001", "type": "E1_unit", "char_range": [2048, 2080],
   "is_real_error": false, "note": "陷阱项：该数值实际正确"}
]
```

`is_real_error=false` 的**陷阱项**用于检验误报率 —— 这是
「误报控制」评分项的直接证据。

输出精确率 / 召回率 / F1 / 错误类型覆盖率。

## 回归防线

`tests/test_audit.py::test_no_false_positives_on_clean_draft`
断言一份**完全正确**的草稿产生**零**发现。任何规则改动引入误报，CI 立刻失败。
