# 真实数据验证报告（第七轮）— P1：可比公司从占位样本换成真实数据

> 起点：`docs/VALIDATION_ROUND3_R4.md` 的 P1（挂了四轮未做）——
> 「相对估值的可比公司数据：目前是离线静态占位样本
> （`pipelines/r4_valuation/model.py::COMPS_POOL`），
> '实际应用价值'评分项需要真实市场数据」。
>
> 输入：`runs/annual25` 的事实库（601857 中国石油，FY2025）
> 运行：`runs/r4-real23`
> 产出：`data/comps/601857_2025A.json`（由 `tools/fetch_comps.py` 生成）

---

## 一、原来是什么样（两个问题，不只是"数据是假的"）

```python
COMPS_POOL = [
    {"name": "可比公司A", "ticker": "000001.SZ", "pe": "12.5", "pb": "1.35", ...},
    ...  # 五条手写样本，连名字都是编的
]
```

### 问题 1：倍数是编的（已知）

它只演示"筛选 → 中位数 → 隐含价值区间"这条链路，不构成任何真实估值结论。
这一点在代码注释与报告风险提示里都写着 —— 属于已披露的局限。

### 问题 2：市值的算法是错的（P1 时新发现）

```python
market_cap = pe * Decimal(targets["net_profit_parent"])   # ← 用**目标公司**的净利
```

这算出的是"目标公司按这个 PE 值多少钱"，却把它当成了可比公司的市值。
前者是相对估值的输出，后者才是输入 —— 概念被颠倒了。

这条比"数据是假的"更值得记：即使换成真实 PE，只要市值仍这样反推，
报告里的"可比公司市值"一栏就永远是错的，而且不会报错。

## 二、换成了什么

### 2.1 三段式数据，每段都有来源

| 数据 | 来源 | 备注 |
|---|---|---|
| 价格 | 新浪财经行情接口 `hq.sinajs.cn` | 带行情时间戳（2026-09-18） |
| 总股本 / 总市值 | 东方财富 push2 接口 | `f84` / `f116` |
| 归母净利 / 归母权益 | 东方财富财报接口 | `PARENT_NETPROFIT` / `TOTAL_PARENT_EQUITY`，法定披露口径、按报告期 |

### 2.2 倍数自己算，不采信接口字段

```
pe = 总市值 ÷ 归母净利润
pb = 总市值 ÷ 归母所有者权益
```

为什么自算：接口直接给出 PE/PB 字段，但其口径未在任何随附文档中标注 ——
是否含少数股东权益、按合并报表还是母公司报表口径，均无从确认。

自己算 + 能对上人工真值，比"采信一个说不清口径的字段"更可核对。
算式写在报告里（`pe = 总市值 ÷ 归母净利润`、`pb = 总市值 ÷ 归母权益`），
读者可用同一份快照里的 `market_cap` 与 `equity_parent` 自己复核。

> 修订（2026-09-27）：此处原写「601857 的 PB 字段给 1.22，而"总市值 ÷ 归母权益"
> 算出 0.86，两者矛盾」。该表述已被证伪：
>
> - 快照 `data/comps/601857_2025A.json` 里 `market_cap = 1,932,701,525,758.08`、
>   `equity_parent = 1,617,287,000,000`，相除得 1.1950，不是 0.86；
> - 本文档 §4.1 自己的结果表里，601857 的 PB 也写着 1.1950 —— 即 §2.2 与 §4.1 自相矛盾；
> - `tools/fetch_comps.py` 从未把接口的原始 PE/PB 字段写进快照，故"1.22"同样无从复核。
>
> 结论：这段"接口口径不透明"的论证方向仍成立（接口字段口径确实未标注），
> 但当时引用的两个具体数字都无法回溯，其中 0.86 与产物直接冲突，已删除。
> 这本身是一次"数字进了报告却谁也说不清"的事故，与本文档要防的正是同一类问题。

### 2.3 数据源可信度有闸门，且闸门验证过

`tools/fetch_comps.py` 抓完数据后，会把 601857 的 FY2025 归母净利与
`data/r5_eval/truth.py`（人工逐页核对年报得到的真值）比对，
不一致直接报错退出、不生成快照 —— 否则一个错的基准会静默污染整条估值链。

实测验证结果：

| 代码 | 接口返回 | 人工核对真值 | |
|---|---|---|---|
| 601857 | 157,302,000,000 | 157,302,000,000 | ✓ 逐位一致 |
| 000722 | 72,137,817.29 | 72,137,817.29 | ✓ 逐位一致 |
| 002716 | 340,185,327.64 | 340,185,327.64 | ✓ 逐位一致 |

三家全部逐位一致，因此采信该接口。

## 三、可比公司怎么挑的（规则写在数据里，不在代码注释里）

快照的 `peer_selection_rule` 字段记录了人工挑选规则，并原样出现在报告里：

> 同属石油天然气产业链（上游勘探 / 一体化 / 油服工程）；
> A 股上市、交易币种一致（倍数无需汇率换算）；
> 不纳入港股/美股同业 —— 那需要汇率与时点对齐，
> 会给「倍数从哪来」引入第二个可争议环节。

样本过滤（在 `_select_peers` 里执行，文字与实现一致）：

1. 剔除目标公司自身（它出现在快照里只是为了验证数据源）
2. 剔除 PE ≤ 0 或 > 100 的异常值
3. 剔除缺 PE 或 PB 的样本
4. 取中位数而非均值（抗异常值）

> 这一层此前有个"描述比实现漂亮"的问题：注释声称做了"行业相同 + 市值同量级"
> 匹配，而代码只做 PE 区间与倍数完备性检查。现改为按实际情况描述，
> 行业匹配的责任明确交给数据层的挑选规则（上面那段文字）。

| 600028 | 中国石化 | 622,886,712,528 | 19.5821 | 0.7502 |
| 600938 | 中国海油 | 1,535,217,513,683 | 12.5753 | 1.9124 |
| 601088 | 中国神华 | 1,002,702,547,874 | 18.9730 | 1.9583 |
| 600346 | 恒力石化 | 115,582,018,486 | 16.3376 | 1.7310 |
| 002493 | 荣盛石化 | 128,364,332,964 | 151.3170 | 2.9446 |
| 601808 | 中海油服 | 57,974,842,800 | 15.0908 | 1.2448 |
| 600583 | 海油工程 | 26,793,410,088 | 12.8540 | 1.0081 |

荣盛石化 PE = 151.3 被规则正确剔除 —— 这条规则第一次有了实际作用
（在占位样本上，五条样本的 PE 全在 10–23 之间，规则从未触发过）。

### 4.2 估值结论的变化

| | 占位样本（`r4-real16`） | 真实数据（`r4-real23`） |
|---|---|---|
| 可比公司数 | 5（编的） | 6（真实，从 7 家中筛掉 1 家） |
| 中位 PE / PB | 15.80 / 1.62 | 15.71 / 1.49 |
| comps 隐含价值 | 10.3795 ~ 12.6350 | 11.6047 ~ 12.1554 |
| DCF 点估计 | 12.2785 | 12.2785 |
| 综合区间 | 10.3795 ~ 12.2785（1.18×） | 11.6047 ~ 12.2785（1.06×） |

区间从 1.18 倍收窄到 1.06 倍，而且 DCF 与相对估值高度吻合 ——
两个方法独立算出来的每股价值落在 ¥11.60 ~ ¥12.28 这个窄带里。
这与第四轮形成对照：那时候是 12 倍宽、两个方法互相矛盾。

> 注意：**这不是"因为换了数据所以结论更可信"**。第四轮的 12 倍宽是量纲错误
> 造成的（见 `VALIDATION_ROUND4_R4_RANGE.md`），与本轮无关。
> 本轮的收益是：相对估值那一端从编的数换成了可核对的数。

### 4.3 报告里新增的"数据来源与时点"段

```
- 快照文件：`data\comps\601857_2025A.json`
- 抓取时间：2026-09-20T04:16:06+00:00
- 财务数据报告期：2025-12-31
- 数据源（price）：新浪财经行情接口 hq.sinajs.cn（含行情时间戳）
- 数据源（shares_and_market_cap）：东方财富 push2 行情接口
- 数据源（financials）：东方财富财报接口，法定披露口径（PARENT_NETPROFIT / TOTAL_PARENT_EQUITY）
- 倍数算式（pe）：总市值 ÷ 归母净利润（本工具自算，不采信接口的 PE 字段）
- 为什么自算而不采信接口字段：实测接口给的 PE/PB 字段口径不透明：…两者矛盾且无法解释
- 数据源验证：抓取后自动比对 data/r5_eval/truth.py…任何一家不一致即拒绝生成快照
- 筛选后可比公司数：6（中国石化、中国海油、中国神华、恒力石化、中海油服、海油工程）
```

这段进了产物契约（`ValuationResult.comps_provenance`），
不是只写在报告模板里 —— 读者据此自己复核每一个数，不必相信我们的转述。

## 五、仍然缺失的

### 5.1 EV/EBITDA 留空

它需要「市值 + 有息负债 − 现金」，而现金与有息负债没有可靠的结构化公开来源
（实测东方财富财报接口不返回这两项）。宁可留空、由 `run_comps` 降级处理，
也不用编的数充数。

→ 报告表格里的 EV/EBITDA 一列现在是空的。这是真实呈现，不是遗漏。

### 5.2 只覆盖 A 股同业

港股/美股同业（如中石化冠德、埃克森美孚）需要汇率换算与时点对齐，
会给"倍数从哪来"引入第二个可争议环节。样本因此偏小（6 家）。

→ 已写进风险提示："样本量为个位数，中位数对单个样本的变动较敏感"。

### 5.3 快照是一次性时点

行情是 2026-09-18 收盘的。报告标注了时间戳，但不会自动刷新 ——
重跑 `tools/fetch_comps.py` 才会更新。这是有意为之的：
估值结论必须能复现，不能每次读都变。

## 六、测试与兼容性

全量：466 passed。

### 快照缺失时显式报错，不退回占位样本

R4 读到坏快照时抛 `CompsDataError`，错误信息里带生成命令：

```
找不到可比公司快照：data/comps/601857_2025A.json
请先运行：python tools/fetch_comps.py --target <代码> --as-of <报告期>

⚠️ 本项目**刻意不提供内置占位样本**：宁可让流水线失败，
也不让报告里出现看起来正常、实际是编造的倍数。
```

### 测试夹具用一个明确标注的测试夹具快照

`data/comps/600519_2025A.json` 是合成样本（`600519` 是 mock 演示数据的主体），
文件里有 `"snapshot_kind": "test_fixture"` 与显式说明，不声称自己是真实数据。

> 这与"不内置占位样本"的原则一致：占位样本的问题是冒充真实数据。
> 一个自称是测试夹具的文件不会冒充任何东西，而它让
> "mock 模型 + 合成样本 + 无需联网"的端到端测试仍然成立。

### 快照路径跟随 `--data`

`default_snapshot_path()` 接受 `data_dir`，由 `ctx.configs["data_dir"]` 传入 ——
测试与演示指向自己的数据根目录，不与真实素材抢同一个位置。

## 七、方法论收获

### 收获 1：换数据源之前，先确认算法是对的

P1 原本的描述是"数据是占位的，需要真实市场数据"。我动手时才发现
`market_cap = pe × 目标公司净利润` —— 即使喂真实 PE，市值那一栏仍然是错的。

"数据是假的"这类问题很容易掩盖"算法是错的"：因为结论本来就不该被信任，
没人会去核对中间量。换成真数据的那一刻，这两个问题会一起暴露出来，
而那时已经很难分清是"数据不对"还是"算法不对"。

### 收获 2：宁可让流水线失败，也不让报告里出现编造的数

快照缺失时 R4 直接报错，不退回占位样本。这条取舍值得写下理由：

- 退回占位样本 → 报告看起来完全正常，里面是编的数。这正是本轮要消除的问题，
  留一条后门等于没改。
- 直接失败 → 演示中断，但错误信息里带着修复命令，30 秒就能恢复。

"看起来正常"比"明显失败"危险得多。这与项目既有的取舍一以贯之
（`SKIPPED ≠ FAIL`、不把"未检查"呈现为"检查通过"）。

### 收获 3：采信一个说不清口径的字段，不如自己算 + 验证

接口直接给了 PE/PB，用起来最省事。但它的口径没有随附文档说明
（是否含少数股东权益、合并还是母公司报表口径），进报告就是一个读者无法复核的数。

改用"自己算 + 与人工核对真值比对"之后：算式写在报告里、读者能用快照里的
`market_cap` 与 `equity_parent` 自己复核，基线还能被三家公司的真值同时验证。
可解释性 > 省事。

> 本收获原先举了「1.22 vs 0.86」作为接口字段"矛盾"的例证，该组数字已于 2026-09-27
> 被证伪并删除（详见 §2.2 修订说明）。但这条收获的方向不受影响 ——
> 正相反：那次事故本身就是"引用了一个产物里查不到的数字"，
> 是"可解释性 > 省事"的又一个正面案例，只不过犯错的是我们自己。

### 收获 4：规则要在真实数据上才会被验证

PE>100 剔除这条规则，在占位样本上从未触发过（五条样本 PE 全在 10–23）。
换成真实数据的第一天，它就把荣盛石化（PE=151.3）挡在了外面。

未被触发过的规则，等于没有被验证过的规则。
