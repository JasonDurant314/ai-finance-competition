## 一、P3：折现参数从"主观"变成"分项可核对"

### 1.1 原来是什么样

```python
"wacc": Decimal("0.095"),
"terminal_growth": Decimal("0.025"),
```

说明文字写着"无风险利率 2.0% + 股权风险溢价 6.0% × β1.1 + 债务成本调整 ≈ 9.5%"——
但那四个数字没有任何出处，读者无法核对，也无法判断是否过时。

### 1.2 现在的取值与出处

无风险利率取真实市场数据：10 年期国债到期收益率 1.69%，
来源为[中央国债登记结算有限责任公司《中债收益率曲线和指数日评》2026 年 09 月 17 日](https://www.chinabond.com.cn/xxwsy/sy_zdgz_ath/202609/t20260917_855412596.html)
（原文："10年期收益率稳定在1.69%"）。

为什么取 10 年期而非 3M/2 年期：估值的显式预测期是 5 年、之后进入永续期，
对应长久期资金成本。同日 2 年期 1.26%、3M 1.18%、10 年期国债期货主力合约
T2612 对应收益率 1.5163% —— 期货隐含收益率更低，与现券口径不同，
本项目采用现券收益率曲线（更常用作无风险利率），并在缓存文件里记录了这个取舍。

WACC 按 CAPM 逐项算出：

```
Ke   = Rf 1.69% + β 1.00 × ERP 5.50% = 7.19%
WACC = Ke × (1 − 债务占比 20%) + Kd 3.10% × (1 − 税率 25%) × 债务占比 20%
     = 6.22%
```

| 分项 | 值 | 性质 | 来源 |
|---|---|---|---|
| Rf | 1.69% | 市场数据 | 中债收益率曲线（带 URL 与日期） |
| ERP | 5.50% | 假设 | 未取到可引用的当期 ERP —— 见下 |
| β | 1.00 | 假设 | 取市场平均 |
| Kd | 3.10% | 推论 | 国债收益率 + 约 140BP 信用利差 |
| 资本结构 | 20% | 推论 | 能源行业大型央企常见水平 |

### 1.3 两处"取不到就如实说"，而不是挑一个来源冒充权威

ERP 为什么没自动抓：它不是交易所挂牌数据，没有唯一权威来源，
不同机构（Damodaran、中证指数、券商研究）口径差异较大。
与其挑一个来源冒充权威，不如直接标注为假设并给出区间（4%–7%）。

β 为什么不做回归：用目标公司自身的历史收益率回归需要一套可靠的历史价格序列，
而本项目只取到当日行情快照，不足以做回归。
用一个来源不明的 β 比用 β=1.0 更危险 —— 前者看起来精确，实际上不可核对。

### 1.4 永续增长率：加了一道上限校验

```
长期通胀目标 2.0% ≤ 10 年期国债收益率 1.69% ？
→ 不成立，下调至 1.69%
```

理由写在代码里：永续增长率若高于无风险利率，等价于假设企业永远以高于国债的
速度增长 —— 那隐含"这家公司最终会吞掉整个经济体"，是永续增长假设最常见的滥用。

> 实际效果：`terminal_growth` 从 2.5%（主观）变成 1.69%（受国债收益率约束）。

### 1.5 新增：把市场隐含的要求回报率算出来并列呈现

这是本轮最有价值的一个发现。

模型用 CAPM 算出 Ke = 7.19%，而市场给这家公司的盈利收益率
（1 ÷ PE = 1 ÷ 12.2866）= 8.14% —— 市场要求 8.14%，模型却用 7.19% 折现。

这不是"算错了"：低利率环境下 1/PE 高企本身可能意味着市场在定价风险溢价上行
或盈利不可持续。但读者必须看到这个差额，否则会把"模型比市场贵"当成
模型的结论，不是当成一个待解释的信号。

因此 WACC 的说明里现在并列呈现两条：

```
市场参照：目标公司 PE 12.2866，隐含盈利收益率 1/PE = 8.14% ——
即市场当前对该公司的要求回报率量级。把它与模型成本率并列看：
若模型明显更低，DCF 会系统性高于市价，**这不是 DCF 的结论，
而是待解释的差异**。（本项目不用市价反向校准折现率 —— 那会让 DCF
退化成把市价重算一遍，失去独立估计的意义。）
```

## 二、P4：真实增速 —— 前提不成立，被闸门拦下

### 2.1 事实库里的两期收入是不可比的

P4 的原始设想是"有了两期真实收入，可用实际增速替代模板 8%"。实测：

| 指标 | 用事实库两期算出的增速 | 真值口径增速 | 可用？ |
|---|---|---|---|
| revenue | +5385.28% | −2.50% | 不可用 |
| operating_profit | −8.11% | 255,286 → 234,579 = −8.11% | 可用 |
| net_profit_parent | −2.55% | 164,676 → 157,302 = −2.55% | 可用 |

`revenue` 的 `2024A` 在事实库里有 14 条候选，选择键选中的是
52,221,000,000（某张分部/大客户表的收入明细行），而真值是
2,937,981,000,000 —— 相差 56 倍，期间与置信度全都相同。

这不是新缺陷，而是第四轮就记录过的局限：
`_best_fact` 无法可靠区分"集团口径"与"同名明细行"。

### 2.2 处置：闸门 + 回退 + 记缺口

```python
g = (revenue - prev.value) / abs(prev.value)
if not (Decimal("-0.5") < g < Decimal("1.0")):
    → 回退模板值 8%，并把缺口写进 gaps
```

闸门区间 `(-50%, +100%)` 是有意放宽的 —— 它要拦的不是"增速偏高"，
而是"明显取错了候选"（5385% 这种）。

产出的假设说明（实际输出）：

> 用两期收入算出的增速 5385.28% 超出合理区间 (-50%, +100%)，
> 判定为取错候选（2024A 取到 52221000000，本报告期取到 2864469000000）——
> 事实库里同一期间有 14 条收入候选，选择键无法区分集团口径与分部明细行。
> 回退模板值 8% 并列为缺口：用一个荒谬的增速跑 DCF 会得到荒谬的每股价值，
> 而且不报错。

同时 `gaps` 里出现 `营业收入同比增速（两期可比收入，已回退模板值）`。

结论：P4 在 601857 上未能落地，但"为什么不落地"现在是可核对的。
闸门在另外两家（`operating_profit` / `net_profit_parent` 增速与真值一致）
本可直接生效 —— 只是 DCF 的驱动项是收入，因此不能改用它们。

## 三、结果与一个必须解释的差异

| | 第七轮 `r4-real23` | 第八轮 `r4-real26` |
|---|---|---|
| WACC | 9.50%（主观） | 6.22%（CAPM + 真实 Rf） |
| 永续增长 | 2.50%（主观） | 1.69%（受国债收益率约束） |
| 收入增速 | 8%（模板） | 8%（模板，闸门拒绝了两期真实值） |
| DCF 每股 | ¥12.2785 | ¥19.9840 |
| comps 隐含 | ¥11.6047 ~ ¥12.1554 | ¥11.6047 ~ ¥12.1554 |
| 综合区间 | 11.60 ~ 12.28（1.06×） | 11.60 ~ 19.98（1.72×） |
| 终值占比 | 74.0% | 82.3% |

区间从 1.06 倍重新张开到 1.72 倍，而且 DCF 与相对估值差了约 60%。

### 这个差异是"折现率降低"的直接后果，但它的量级值得怀疑

```python
# 按当前模型反推：市场对 601857 的定价对应多少永续增长？
cap          = PE × 归母净利 = 12.2866 × 157,302,000,000 = 1.933 万亿元
equity_model = DCF 每股 19.9840 × 股本 183,020,977,818 = 3.658 万亿元
```

模型给股权价值 3.66 万亿，市场给 1.93 万亿 —— 模型高 89%。
而无论怎么调增长率都补不平这个差（我验算过：即使把永续增长率归零，
模型仍高于市价）。差异来自自由现金流本身，不是来自终值假设。

逐项看，`FCFF = EBIT×(1−税率) + 折旧摊销 − 资本开支 − 营运资本增加`：
模型用的收入增速 8%、资本开支占收入 6%、折旧摊销占收入 5% ——
对一家成熟能源公司，资本开支占比很可能被低估（能源行业维持性资本开支
通常显著高于收入的 6%），而收入增速 8% 对一个成熟一体化石油公司也偏高。

这两条都是模板值（属"观点"），不是从事实库推出的。
本轮把折现率这一端做实了，反而把另一端（经营假设）的薄弱暴露得更清楚。

### 记录

- 本轮没有调整经营假设去"把 DCF 拉回市价附近" —— 那是拿结论凑结论
- 三条经营假设（`revenue_growth` / `capex_ratio` / `da_ratio`）现在仍是模板值，
  报告中明确标注为观点
- 下一轮若继续做 R4，该做的是经营假设（尤其是资本开支占比），
  不是继续调折现率

## 五、方法论收获

### 收获 1：把参数做实之后，别的地方会显得更虚

P3 之前，"DCF 给 ¥12.28、comps 给 ¥11.60~12.16"看起来两个方法高度吻合。
把折现率换成有出处的值之后，DCF 跳到 ¥19.98，差异暴露出来。

这不是"改坏了"，而是原来的一致性本来就是假的 ——
它建立在"用 9.5% 这个凑巧合适的数"之上。一个凭感觉调的参数
可以让两个方法看起来一致，而这种一致没有任何信息量。

### 收获 2：区分"取不到"与"随便取一个"

本轮有两处明确拒绝取数：ERP（没有唯一权威来源）与 β（没有历史序列可回归）。
两处的处置都是直接标注为假设 + 给出区间，不是挑一个来源冒充权威。

理由写在缓存文件里："用一个来源不明的 β 比用 β=1.0 更危险 ——
前者看起来精确，实际上不可核对。"

### 收获 3：呈现差异，而不是消除差异

模型成本率 7.19% vs 市场隐含 8.14% —— 我没有用市价反向校准 WACC
（那会让 DCF 退化成把市价重算一遍），而是把这个差额写进假设说明。

一个被真实呈现的 60% 差异，比一个被参数调平的 0% 差异有价值得多。
前者告诉读者"这里有个需要解释的东西"，后者只说明"参数被调到刚好吻合"。

### 收获 4：闸门要能拦住"荒谬"，而不只是"异常"

增速闸门取 `(-50%, +100%)` —— 对一家成熟公司来说 8% 也不算低，
但这个区间有意放宽：它要拦的是 5385% 这种"明显取错候选"，
不是替分析师判断"多少增速合理"。

判据的职责边界要清楚：闸门负责拦"不可能"，不负责拦"不好"。
后者是人的判断，写进假设说明里由人核查。
