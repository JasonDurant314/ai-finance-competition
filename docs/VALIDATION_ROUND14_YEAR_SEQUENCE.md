## 二、怎么找到解法的

第十三轮结束时，p7 五年摘要表的 `资本性支出` 行有三个候选：

```
269,089,000,000  scope=consolidated  period=2025A   ← 真值（2025）
275,849,000,000  scope=consolidated  period=2025A   ← 其实是 2024
275,393,000,000  scope=consolidated  period=2025A   ← 其实是 2023
```

三条置信度、口径、单位全同，当时的结论是"没有任何信号能把它们分开"。

本轮换了问法：不再问"能不能区分这三个数"，而问"这张表有没有别处写了年份"。
dump 整张网格后看到 r5：

```
注：（ | 1 | ）截至 | 2021 | 年 | 12 | 月 | 31 | 日、 | 2022 | 年 | ...
```

年份一直印在这张表里，只是印在脚注不是表头。

### 先验证坐标能不能直接用（不能）

脚注的 x 区间是 144 → 507（正文排版），数据列的 x 区间是 311 → 527。
两套坐标不对齐，所以不能"把脚注年份按坐标配到列上"。

### 再用两处独立证据确定方向

| 表 | 期间信息来源 | 数据列方向 |
|---|---|---|
| p7 表 0 | 表头明写 `2025 年 \| 2024 年 \| 2023 年 …` | 从新到旧 |
| p7 表 3 | 脚注 `2021 → 2022 → … → 2025`（升序） | 值 269,089 → 251,323（从新到旧） |

两处都指向同一个排版约定：数据列从左到右 = 年份从新到旧。
于是规则确定：N 个数据列 + N 个连续年份 → 按从新到旧分配。

## 三、★ 先量再改，以及被自己的测量否掉两次

第十三轮我加过一条守卫（"行内期间塌陷"），写完之后才在真实年报上量 ——
结果 `needs_review` 从 159 涨到 529、可用 `equity_parent` 从 16 降到 0，
一条守卫把"个别指标可能取错"放大成"整库不可用"，只能整条删除。

判据的杀伤半径必须在启用之前量出来。本轮先写了量测工具
（`tools/year_sequence_report.py`），在 987 张真实表上量。

### 否掉第一次：守卫"期间字典为空"

第一版守卫是 `if not col_period`（只在期间字典为空时介入）。量出来：
命中 50 张，但目标表不在其中 —— 它的 `col_period` 非空。

### 否掉第二次：守卫"期间缺列"

第二版改成"期间没覆盖全部数据列"。量出来：表 1/表 2 被误覆盖
（它们的期间本已正确），而目标表仍不命中。附带损害出现、目标未解决。

当时我停下来并决定不启用，把三层原因写进文档。这一步是对的 ——
它逼出了第三次、也是正确的判据。

### 第三次（正确）：期间碰撞

两个不同的数据列代表两个不同的年份，不可能共享一个期间。
出现碰撞就说明映射坏了，不是"已经处理过"。

实测目标表的形态正是如此：

```
col1 269,089  period=''         ← 没拿到期间
col2 275,849  period='2025A'    ┐ 同一期间出现两次
col3 275,393  period='2025A'    ┘
col4 274,494  period='2024A'    ┐ 同一期间出现两次
col5 251,323  period='2024A'    ┘
```

而 p7 表 0/1/2 每个数据列各有一个互不重复的期间 → 不碰撞 → 不动。

「碰撞」比「缺列」精确得多：命中数从 67 张降到 4 张（0.4%），
而目标表在两者中都命中 —— 说明收紧判据只去掉误报，没有去掉正例。

## 四、另外两处必须一起修的地方

规则在隔离测试里对，但生产上仍不生效，另有两条独立原因：

### 4.1 脚注被算成了"数据列"

目标表 `data_start = 0`（首行即数据、没有表头行），而 `_data_columns` 的判据是
"任一行出现过数字" —— 脚注里的 `12` `月` `31` `日` 也是"数字"，
于是数据列从 5 撑到 18。

已修：加 `_footnote_row_start`（只认以「注／附注」开头的行）排除脚注行；
另加 `_majority_data_columns`（"任一行有数字" → "多数行有数字"）。
实测数据列 18 → 5。

> 没有改 `_data_columns` 本身 —— 它被 `periods_of_columns` 等三处使用，
> 收紧它会牵动所有走行导向的表。新判据只给本规则用一个兄弟函数。

### 4.2 年份与数据列取自同一个网格

排除脚注后，年份也被排除了 —— 而年份正好在脚注里。
已修：给 `periods_from_year_sequence` 加 `year_grid` 参数 ——
数据列从 `body`（脚注前）取，年份从整表取。

### 4.3 ★ 年份出现了两次，按"次数"判等会永远不成立

修完 4.1/4.2 后规则仍然不命中。把判据逐条摊开后看到：

```
扫描到的年份 = [2025,2024,2023,2022,2021, 2021,2022,2023,2024,2025]（10 个）
来自行 = [(0, [2025,2024,2023,2022,2021]),   ← 数据区上方的期间表头行
          (6, [2021,2022,2023,2024,2025])]   ← 脚注
```

年份在整表里出现两次（表头一次、脚注一次），共 10 个，
而判据 1 要求"恰好等于数据列数 5" → 永远不成立。

已修：按去重后的个数判等。两处序列方向相反（表头从新到旧、
脚注从旧到新）但集合相同，去重后 {2021..2025} 恰好 5 个、连续、无重复。

> 这个坑很典型：判据的意图是"年份集合的大小等于列数"，
> 写出来却成了"年份出现的次数等于列数"。两者在只有一处年份时等价，
> 一旦有两处就分道扬镳 —— 而只有目标表有两处。

## 五、效果

### 5.1 目标表终于正确

```
资本性支出行  269,089 | 275,849 | 275,393 | 274,494 | 251,323
对应期间      2025A   | 2024A   | 2023A   | 2022A   | 2021A
```

### 5.2 capex 候选从 3 条收敛到 1 条

| | 关闭规则 | 启用规则 |
|---|---|---|
| 601857 的 2025A capex 候选 | 3 条：275,849 / 275,393 / 269,089 | 1 条：269,089 |

R4 的"分歧即不取"因此自动解除，capex 变成事实值：

```
capex_ratio_of_revenue = 0.0939   ← 事实
依据：2025A 资本开支 269,089,000,000 ÷ 营业收入 2,864,469,000,000 = 9.39%
gaps = []                          ← 所有缺口清空
```

> 9.39% 正是第九轮人工核算出的真值，也是十一轮以来一直写在
> "已知限制"里的那个数。现在它是从事实库自动算出来的，不是抄进去的。

### 5.3 DCF 与相对估值的差距收窄到十轮以来最窄

| 轮次 | DCF | 与相对估值（¥11.60~12.16）的差距 |

| 第八轮 | 19.98 | 60% |

| 第十一轮 | 22.54 → 18.11 | 49% |
| 第十三/十四轮（capex 取不到） | 19.43 | 67% |
| 第十四轮（capex 取到） | 14.04 | 21% |

### 5.4 A/B 全量对照

| | 关闭 | 启用 |
|---|---|---|
| 事实总数 | 1055 | 1048 |
| needs_review | 209 | 209（不变） |

唯一有实质影响的指标就是 capex —— 而这正是目标。
