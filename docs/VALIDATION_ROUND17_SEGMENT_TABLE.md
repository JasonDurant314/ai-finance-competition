# 第十七轮验证 —— 三处"口径不一致"，让分部表从 0 条候选变成 3 条

> 目标：处理剩下三项里的「002716 分部表双『合计』列」。
> 查下去发现它只是症状，底下压着三处各自独立的口径不一致。

---

## 一、结论速览

| 项 | 结果 |
|---|---|
| 症状 | 002716 的两张分部合同表产出 0 条候选（`aligned=False 数值列仅 0 列`） |
| 根因 1 | 多级表头：`data_start_row` 把表头第二层当成了数据行 → `data_start=1`（应为 4） |

## 二、根因 1：多级表头

002716 的分部合同表是两层列头：

```
r0  合同分类 | 分部1 | 分部1 | 分部2 | 分部2 | 本期数 | 本期数 | 合计 | 合计
r1  合同分类 | 营业收入 | 营业成本 | 营业收入 | 营业成本 | 营业收入 | 营业成本 | 营业收入 | 营业成本
r2  业务类型 |  |  |  |  |  |  |  |
r3  其中：   |  |  |  |  |  |  |  |
r4  有色金属及其制品 | … | 12,371,785,621.02 | …
```

`data_start_row` 的判据是"第一个含数据数字的行"，而 r1 里的
`营业收入`/`营业成本` 不含数字 → 它一路扫到返回 1。
于是"数据区"只剩 2 行真数据，`_majority_data_columns`（要求 40% 的行）判出 0 列。

修法：表头层之后的连续标签行也算表头 —— 不含任何数字形状的格、
且非空格都是短标签（≤6 字）。遇到第一个含数字的行就停。

> 这条修法被测试拦下过一次：公告表的
> `["序号","公司名称","营业收入"]` 后面是 `["1","A子公司","4560万元"]`，
> 而 `"1"` 正是数字。第一版只查 `_is_data_number`（它把 1..31 当日期碎片，
> 为 "12 月 31 日" 设计），漏掉了 `"1"`。改成"任何数字形状的格都停"。

## 三、根因 2：cells 与网格的文本口径不一致

修完根因 1，`data_start_row` 正确返回 4，但对齐仍报 `数值列仅 0 列`。
把三个数并排打出来才看清：

```
_data_columns（看网格）        = [5, 6, 7, 8]     ← 正确
全表数字格（看 cells）          = 0 个             ← 矛盾
```

原因：PDF 把数字按行折断了。网格里的值是修复过的
`'12,371,785,621.02'`，而 `cells` 里保留原始形态 `'12,371,78\n5,621.02'`；
`_is_numeric_text` 用 `fullmatch` 且不含 `\n`，于是一个数字格都认不出来。

修法：对齐前对 `cells` 做一次折行修复（浅拷贝，不动调用方的字典）。

> 这是"调用方与工具口径不一致"的第三个实例（前两个：
> `tools/year_sequence_report.py` 用了旧判据、`scope_hint` 与 `carry_header`
> 用了不同维度的键）。三者都不报错，只是结果静默地不对。

---

## 四、根因 3：判据只看单层

`detect_segment_total_col` 见两个含「合计」的列就返回 `None`
（理由是"无法判断哪列代表集团整体"）。但那两列都是集团口径，
只是分别装营业收入与营业成本 —— 返回 `None` 的代价是整表口径
全部退回 `consolidated`，与分部明细撞成"同表多口径冲突"。

修法：返回集合，多个合计列都标 `segment_total`。
于是 `AlignedGrid.segment_total_col` → `segment_total_cols`，
`_segment_scope` 改成按集合判定。

### 4.1 顺带修掉判据 2 的一个盲点

判据 2（"至少 2 个分部名列"）原先要求列头不含数字 ——
对 601857 成立（`油气和新能源`），但 002716 的分部名列头是
`分部1营业收入`，含分部编号，于是全被排除 → 返回 `None`。

改成两条任一成立：

* (a) 至少 2 列是"纯分部名" —— 不含报告年份、也不是财务科目名（601857 ✓）
* (b) 拼接头里出现 「分部」二字 —— 分部报告的自称（002716 ✓）

> (a) 里"排除报告年份"那一条是实测教训，保留：601857 的标题行
> `(a) 2025 年度及 …` 的日期碎片会与分部名落在同一列，拼成
> `'2025 年油气和新能源'` —— 那是标题噪声，不是那一列的语义。
