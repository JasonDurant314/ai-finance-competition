# 真实数据验证报告（第四轮）— 估值区间宽度诊断

> 起点：`docs/VALIDATION_ROUND3_R4.md` 第四节的 P2 ——
> `runs/r4-real9` 给出 ¥10.3795 ~ ¥124.4143（12 倍宽），
> 当轮推测原因是"上下限取并集极值、中值取等权平均"这个组合。
>
> 推测不成立，已被证伪。区间宽是两个静默错误造成的。
>
> 输入：`runs/annual22`（601857 中国石油 2024 + 2025 两份年报，离线确定性路径，9 分钟）
> 运行：`runs/r4-real16`
> 修正后：¥10.3795 ~ ¥12.6350（1.22 倍宽），中值 ¥12.01195

---

## 一、结论先行

12 倍宽区间由一个量纲错误直接造成：

```
DCF   每股价值  ¥124.4143   ← 异常端
comps 每股价值  ¥10.3795 ~ ¥12.6350   ← 正常端（本身就窄，1.22 倍）
```

DCF 端整条链条被一个放大 100 倍的现金值推高：

| 科目 | 错误值 | 正确值 | 后果 |
|---|---|---|---|
| `cash_and_equivalents` 2025A | 20,616,200,000,000 | 206,162,000,000 | 净债被推成 −20.44 万亿 |
| `net_debt` | −20,442,206,000,000 | −122,861,000,000 | 权益价值虚增约 10 倍 |
| `equity_value` | 22,770,435,884,392 | 2,451,090,884,392 | |
| `value_per_share` | 124.4143 | 13.3924 | 区间宽度 12.0× → 1.29× |

阈值对照：2025 年 12 月 31 日中国石油总资产 2,828,017 百万元，
货币资金 206,162 百万元（占资产 7.29%）。
错误值 20,616,200 百万元是总资产的 7.29 倍 —— 一家公司的现金不可能是它总资产的 7 倍。

## 二、缺陷 1：行标签里的单位被漏看

### 现象

同一份年报里，同一个物理数字 `206,162` 出现在至少 4 处，口径都是
人民币百万元（2025 年末合并现金及现金等价物）：

| 页 | 原文形态 | 抽出的值 | 判定 |
|---|---|---|---|
| p28 | 「现金及现金等价物年末余额 206,162」（表头人民币百万元） | — | — |
| p29 | 「减：现金及现金等价物 206,162」（表头人民币百万元） | — | — |
| p95 | 「期末现金及现金等价物余额（人民币百万元） \| 206,162」 | 206,162,000,000 | ✓ |
| p176 | 现金流量表「年末现金及现金等价物余额 \| 206,162 \| 172,477 \| 35,673 \| 25,139」 | 20,616,200,000,000 | ✗ 错 100 倍 |

### 根因：单位优先级的链条上缺一环

原实现的单位优先级是 单元格 → 列头 → 表级/页级声明，缺 行标签：

```python
unit_source = "cell"                                        # 单元格自带
if not unit: unit = unit_in_label(header[j])                # 列头
if not unit: unit = unit_hint or find_unit_declaration(...)  # 表级/页级
```

而 p95 那张表列头只有 `2025 / 2024`，单位写在行标签里：

```
期末现金及现金等价物余额（人民币百万元） | 206,162 | 172,477
```

行标签被跳过 → 单元格无单位 → 落到表级/页级声明 → 量纲错 100 倍。
quote 回读照过（`206,162` 确实印在原文里），量纲族校验也过
（元与百万元同属 `money` 族），因此没有任何闸门能拦住。

### 修复

单位优先级补上 行标签，两条抽取路径都要改
（`pipelines/r1_extract/table_facts.py`）：

```
单元格自带  →  行标签  →  列头  →  表级/页级声明
```

- `extract_table_facts`（行导向）：行标签是 `row[0]`，`unit_source = "row_label"`
- `extract_statement_facts`（列导向）：行标签就是 `subject`
  （`subject_of_row` 取本行最靠左的非数值文字格，正是科目名那一格）

> 踩坑记录：列导向路径第一版写成 `unit_in_label(label)`，而该作用域里没有
> `label` 这个名字（用的是 `subject`）—— 7 个测试立刻报 `NameError`。
> 是测试抓住了它，不是代码审查。

### 效果

`runs/annual22` 的 p95 现金现在抽成 `206,162,000,000`（原来 `20,616,000,000,000`）。

### 仍然存在的问题

p176 那张表自身的表头判据缺失：四个数据列是
「2025 年度 / 2024 年度 / 2025 年度 / 2024 年度」（合并 + 母公司并排），
而行标签 `现金及现金等价物的年末余额` 里没有单位。页面上同时印着
归属母公司报表的「单位：元」与归属合并报表的「人民币百万元」，
程序无法从这两者中判定该用哪个 —— 这不是判据不够，是信息本身有歧义。

修法不是"再猜一次"，而是让这个错误不再能污染结论（第三节），
以及让它在下游可被核对出来（第七节）。

## 三、缺陷 2：跨表量纲冲突没有闸门

### 为什么原来的守卫抓不住

`FactLedger._check_internal_conflict` 只在同一张表内比对
（`_same_table`：同页 + bbox 纵向重叠）。这条设计是对的 ——
上一轮把它放宽到跨表时，`needs_review` 从 145 涨到 562（占全库 63%），
因为年报里同一主体的合并数 / 子公司数 / 分部数量级天然不同。

但 p95 与 p176 是两张不同的表，于是 `206,162,000,000` 与
`20,616,200,000,000` 谁也没被标记，两条都干净地进了事实库。
R4 的 `_best_fact` 在两者之间打平（期间相同、置信度都是 0.95、口径都是合并），
最后的并列打破键是 `len(str(f.value))` —— 字面上更长的那条胜出，
也就是被放大 100 倍的那条。这个并列打破键本身就是缺陷：
它系统性地偏好量级更大的值。

### 修复：用资产负债表恒等式做闸门，而不是"量级离群"

新增 `FactLedger.check_scale_plausibility()`（`agent/evidence/store.py`），
对货币资金类指标施加两条有会计含义的上界：

| 锚点 | 上界 | 理由 |
|---|---|---|
| `total_assets` | 1.5 倍 | 货币资金本身就是资产的一部分，不可能显著超过资产总额 |
| `revenue` | 3.0 倍 | 现金也不可能显著超过年度营业收入 |

为什么用恒等式而不用"量级离群"：恒等式被质疑时能解释，离群不能。
阈值放到 1.5 / 3.0 这种宽到不会误伤的水平 —— 本闸门要抓的是
100 倍级的量纲错误，锚点自身再偏 2–3 倍也不影响判断。
锚点取同一 `(doc_id, entity, period)` 下的最大值：只有当事实连
最宽松的锚点都撑不住时才算越界。

### 实测效果（`runs/annual22`）

```
scale_implausible: 4
  cash_and_equivalents 2025A  20,616,200,000,000 vs 2,828,017,000,000 = 7.29×
  cash_and_equivalents 2025A  17,247,700,000,000 vs 2,828,017,000,000 = 6.10×
  cash_and_equivalents 2024A  17,247,700,000,000 vs 2,759,237,000,000 = 6.25×
  cash_and_equivalents 2024A  24,900,100,000,000 vs 2,759,237,000,000 = 9.02×
```

精准命中 4 条，零连带误伤。被标记的事实带完整证据链：

```
量纲不合理：cash_and_equivalents = 20616200000000 元（evd_…）
达到同期 total_assets = 2828017000000 的 7.3 倍，超过恒等式上限 1.5 倍。
货币资金本身就是资产的一部分，不可能显著超过资产总额或年度营业收入 ——
最可能的原因是同一指标在不同表里被赋予了不同的单位。
锚点事实：fct_tbl_40dbb0efd7a87119
```

闸门不猜哪个对，只把越界的那条排除出可用集（`needs_review` 的事实
被 `_best_fact` 跳过）。

> 设计取舍：也可以让闸门"保留更合理的那条、丢弃另一条"。
> 这里没有这么做 —— 一条事实是否正确与它是否越界是两件事。
> 闸门只回答"这条不能直接用"，把判断留给人。

## 四、缺陷 3：列序回退把期间派给了错误的列

独立于量纲问题的第二个静默错误，同样由本轮诊断发现。

### 现象

`periods_of_columns` 的第③条兜底（"表头判不出期间时按列序推断年份"）
在真实表格上大面积错标：

```
表头 ["项目", "2025", "年", "2024", "年"]      ← 中国石油 p95，年份被分列
旧输出 col0→2025A  col1→2025A  col2→2024A  col3→2024A  col4→2023A
                              ↑ `年` 这个片段列拿到了 2024A，
                                现金 206,162 因此从 2025A 漂到 2024A
```

### 四个坑

| # | 缺陷 | 说明 |
|---|---|---|
| 1 | 序号从 0 起算 | `enumerate(unfilled)` 的下标是"未指派列表里的序号"，不是表格列号。首列表头通常为空（`项目`/`类别` 那一格），于是"第一个无期间列"被当成最新期间，整行年份错位 |
| 2 | 变动率列被当成一期 | `本年比上年增减` / `同比` / `变动` 列的是"两期之差"，不是某一期。给它安一个年份等于凭空造出一期数据 |
| 3 | 表头片段列 / 季度列被当成年度 | `2025 \| 年 \| 2024 \| 年` 里的 `年` 是分列产生的独立列；`第一季度…第四季度` 若被标成 2025A/2024A/2023A，那是"四个季度"被写成"四个年份" |
| 4 | 假设标签列就是 col0 | 601857 2024 年报 p8 的科目列在 col1、期间列从 col0 起（"追溯调整前后"对比表把年份印在科目列上方）。跳过 `j=0` 会让整行年份整体错位一格 —— 2024 年的收入被标成 2025A |

### 修复

判据③ 的适用条件收紧为：

1. 只有当所有表头行合起来仍然一个期间标签都没有时才启用。
   表里只要存在期间标签，判据③ 的前提（"这些列按期间排列"）就不需要靠猜 ——
   猜只会与已知标签打架。这条是本节最重要的修正。
2. 该列确实含数字（新增 `_data_columns()`：数据区里出现过可解析数字的列号）。
3. 该列列头含期间词（新增 `_PERIOD_COLUMN_WORDS`：本期/上期/期末/年初/年度…）。
4. 该列不是变动率列（新增 `is_change_column()`）。
5. 标签列永远排除（新增 `_label_column()`：数据区里非数字文本最多的那一列，
   平票取最靠左）。这条守卫对所有判据生效 ——
   p8 表头首格 `2023` 落在标签列上，若不排除会被当成"该列是 2023 年"。

序号改用 `j - unfilled[0]`（真实列号之差）。
另外整条兜底加 `doc_period.endswith("A")` 前置条件 ——
季报/半年报的"上一期"语义不同（上年同期 vs 上季度），本来就不该套用年报的列序假设。
多行表头用新增的 `periods_from_header_rows()` 逐行提取后合并（先到先得）。

### 修复后

```
["项目","2025","年","2024","年"]                    → {1:2025A, 3:2024A}
["","2025 年","2024 年","本年比上年增减","2023 年"]    → {1:2025A, 2:2024A, 4:2023A}
["","第一季度","第二季度","第三季度","第四季度"]          → {}   ← 不再臆造年份
["项目","金额","占比","人数"]                          → {}   ← 无期间词，不推断
["项目","期末余额","期初余额"]                          → {1:2025A, 2:2024A}   ← 目标场景仍工作
```

## 五、缺陷 4：基年与基年数值来自不同年度

`base_year` 在 `assumptions.py` 里硬编码为 2024，而 `base_revenue` 取的是
`_best_fact` 选出的最新期间事实（2025 年报里就是 2025A）：

```json
{"base_year": 2024, "base_revenue": 2864469000000}
```

2,864,469 百万元是2025 年的收入（2024 年是 2,937,981 百万元）。
报告里"基年"与"基年收入"指向两个不同年度，DCF 的显式预测期因此整体前移一年。

修复：新增 `_fact_year(fact_id, fs)`，从事实自身的 `period` 反查年份。
修复后 `base_year = 2025`，与 `base_revenue` 同期。

> 这与第三轮修的"取值与说明不一致"是同一类：同一条结论的两个组成部分
> 由两处独立决定。第三轮统一了 `_best_fact`，这一轮统一了基年。

## 六、关于 `weighting_note`（P2 原始推测的处置）

P2 的推测已被证伪：修掉量纲错误后区间是 1.22 倍宽；comps 端一直是
10.38~12.64（1.22 倍），DCF 端原本是 124.41 ——
宽度的全部来源是 DCF 端的量纲错误，不是合成口径。

但 P2 指出的表述问题确实存在，已修：

- 原 note 说"中值取 DCF 与相对估值中值的等权平均"，而上下限取并集极值 ——
  读者会把"等权"顺推到上下限，误以为区间是加权结果。实际两者口径不同：
  DCF 是点估计、comps 是区间。新 note 把这一点写在最前面，
  并代入具体数值，让读者能自己验算。
- 新增不变量断言 `lo <= mid <= hi`（可判定，不是"看起来合理"）。
- 明确写出代价："区间宽于任一单独方法，不代表分歧被放大"。

修复后 DCF 值（12.2785）落在相对估值区间（10.3795 ~ 12.6350）之内 ——
两个方法不再互相矛盾，这正是口径统一后的直接结果。

### 未解决的局限

A. `_best_fact` 无法可靠地"从多条候选中挑出集团口径的那一条"。

年报里同一个指标名会出现在很多张表里 —— 合并利润表的「营业收入」、
分部报告的「营业收入」、大客户集中的「营业收入」。它们的
期间与置信度完全相同，选择键分不出来。

实测：`cash_and_equivalents` 2025A 选到了 2,289（百万元，
某子公司资产负债表行），而合并口径是 206,162（百万元）—— 相差 90 倍。
后果：`net_debt = +810.12 亿` 而非 `−1,228.61 亿`，每股价值 12.2785 而非 13.3924。

试用过两种判据，都被实测否掉，因此没有留在代码里：

| 判据 | 为什么被否掉 |
|---|---|
| 锚点比例带（占资产总额 10%–80%） | 中国石油的货币资金只占资产 7.29%，低于下限 → 带内一条候选都没有，判据空转 |
| 同文档跨页重复出现（集团数印在多页，子公司明细只印一页） | 事实库对同 id 已去重，且多文档事实混在一个 FactSet 里，"跨页计数"无法还原真实重复印刷 —— 实测让「522.21 亿」这类被重复抽到的明细行反超了真实营业收入，比不改更糟 |

修法在 R1 侧：让表格抽取能判定"这是合并利润表的营业收入行，
那是分部/大客户表的同名行"，不能在下游靠启发式猜。
这件事已列入待办，尚未实现。

B. 结果需要人工核对，这一点已经工具化。

既然自动判据守不住上面这条，就必须让"错在哪里"能被快速发现。
新增 `tools/verify_truth.py`：把事实库的取值与人工逐页核对的真值逐项比对
（真值与 R5 评测集共用同一份 `data/r5_eval/truth.py`，避免两处各写一套）。

工具本身也踩了两个坑，都记在代码注释里：

- 主体写法不统一：事实库的主体名是正文里出现的名字，
  而证券简称与正文全称可以毫无字面关系 —— `000722` 的真值简称是 `湖南发展`，
  正文全称却是 `湖南能源集团发展股份有限公司`（`湖南发展` 甚至不是它的子串）。
  可靠做法是走文档文件名（`000722_湖南发展_2025年年度报告_…`），
  让主体归属由"这条事实出自哪份文件"决定，不能靠字符串猜。
- 舍入与取错必须分开统计：源表常只印到万元或整数，
  相对差 ≤0.01% 属于四舍五入（无需处理），>0.01% 才是实质不符（要人工查）。

### 实测（`runs/annual23`，四份年报，886 条事实）

```
命中 8 / 舍入相符 2 / 不符 6（可比 16），缺失 8
```

| 主体 | 2025A（估值实际使用的期间） | 2024A |
|---|---|---|
| 601857 中国石油 | 收入 ✓ 归母净利 ✓ 总资产 ✓ | 收入 ✗ 归母净利 ✗ 总资产 ✗ |
| 000722 湖南发展 | 收入 ≈ 归母净利 ✓ 扣非 ✓ | 收入 ✓ |
| 002716 湖南白银 | 收入 ≈ 归母净利 ✓ | 收入 ✓ |

对照修复前的 `runs/annual21`（同一工具、同一真值）：

```
命中 3 / 可比 6，缺失 18        ← 000722、002716 的主体完全匹配不上
```

结论：三家主体的 2025A 关键科目全部命中或仅差舍入，
6 条实质不符全部集中在 601857 的 2024A —— 同属局限 A
（取到了分部报告/大客户集中表的同名行）。2024A 目前只用于比较，
不进入 DCF 基年，因此不影响本轮估值结论，但这条差异是真实的、必须记录在案。

## 八、新增的防回归测试

| 文件 | 用例 |
|---|---|

## 十、方法论收获

区间宽度是一个诊断信号，不是噪声。

第四轮的起点是一个"看起来像方法论分歧"的现象（12 倍宽区间）。
如果当时按 P2 的推测去调合成口径 —— 加权、取中位数、砍掉极端端 ——
区间会"变好看"，而 −20.4 万亿的净债会原封不动留在报告里。
该做的是顺着区间往回追，直到找到那个把 DCF 推高一个数量级的输入。

闸门的分工在本轮变得更清楚：

| 闸门 | 为什么拦不住这次的错误 |
|---|---|
| 量纲族校验 | 元与百万元同属 `money` 族 |
| quote 回读 | `206,162` 确实印在原文里 |
| 同表冲突守卫 | 两条事实在不同的表里（放宽它会让噪声涨 4 倍） |
| 资产负债表恒等式 | ← 拦住了：现金不可能超过资产总额 |

最后拦住它的是一条关于"这个世界应该长什么样"的知识，
不是一条关于"数据应该长什么样"的规则。
这与第三轮的结论（EBIT 率合理性闸门挡住了"净利润冒充 EBIT"）是同一个方向：
依赖指标语义的合理性判据，覆盖那些形态类闸门覆盖不到的区域。

以及一条反向的教训：本轮我两次试图用启发式（锚点比例带、
跨页重复出现）去解决"选哪条候选"的问题，两次都被实测否掉，
第二次甚至比不改更糟。启发式只有在能被真实数据证伪时才值得留下 ——
不能因为它在直觉上合理就留在代码里。这两条判据因此没有进入最终实现，
只作为"试过且失败"记录在本报告中。
