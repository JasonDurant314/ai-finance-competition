# 第十六轮验证 —— 报表表头必须按口径继承

> 第十五轮用恒等式联合选择修好了 000722 的 2025A，但它的 2024A 无自洽三元组。
> 本轮去查为什么 —— 根因是报表表头的继承键写错了，而这一处错误
> 让全库 30 条事实白白进了复核队列。

---

## 一、结论速览

| 项 | 结果 |
|---|---|
| 根因 | `doc_header` 按文档单键存表头；而合并表与母公司表的页序交错，后出现的表头覆盖先出现的 |
| 新判据 | 表头键改为 （文档, 口径） —— 与 `scope_hint` 用同一个判据 |
| 效果 1 | 全库 `needs_review` 209 → 179（−30） |
| 效果 2 | 000722 的 2024A 从"几乎没有数据"变成有自洽三元组 |
| 目标公司 | 完全不受影响（DCF ¥14.0394、四项事实值、`gaps=0` 全部一致） |
| 测试 | 512 passed（无新增，改动由现有测试覆盖 + 真实数据验证） |

---

## 二、症状与排查

第十五轮结束时：

```
000722 的 2024A：无自洽三元组
```

而该期间几乎没抽到东西 —— 只有 p159 一张子公司汇总表的杂项：

| 指标 | 2024A 候选 |
|---|---|
| 总资产 | 38,773,904.93（p159 资产合计） |
| 总负债 | 5,163,730.32（p159 负债合计） |
| 所有者权益 | 13,444,069.85（p159 按持股比例计算的净资产份额） |

真值（3,777,520,118 / 394,536,433）明明在库里，却带着 `2025A`。

### 2.1 第一步：定位到"两条报表交错"

把 p73–p92 每张表的表头与首行摊开：

```
★表头 p73 表0  表头=['项目','期末余额','期初余额']  r1='流动资产：'      ← 合并
  续表 p74 表0  表头=[]                            r0='使用权资产'      ← 合并
  续表 p75 表0  表头=[]                            r0='租赁负债'        ← 母公司
★表头 p75 表1  表头=['项目','期末余额','期初余额']  r1='流动资产：'      ← 母公司
  续表 p76 表0  表头=[]                            r0='其他流动资产'    ← 母公司
```

合并资产负债表跨 p73–p76，母公司资产负债表插在 p75。这是一个交错结构。

### 2.2 第二步：验证"表头继承"本身是对的

把 `carry_header` 正确接上后，用生产函数直接跑 p76 表0：

```
p76 表0:  3,797,417,361.30  period='2025A'   ← 本期
          3,777,520,117.62  period='2024A'   ← 上期（真值）
```

机制没问题，生产路径上没生效。

### 2.3 第三步：找到那一行代码

```python
doc_header: dict[str, list[str]] = {}      # ← 按文档单键
...
if tstats.get("statement_table") and not tstats.get("carried_header"):
    hdr, _ = _bh(_mf(grid).grid, alias_map)
    if hdr:
        doc_header[doc_id] = hdr           # ← 后出现的表头覆盖先出现的
```

p75 表1 一建表头，p73 的合并表头就被覆盖了。于是：
* p76（合并表的续表）继承到母公司表的表头 → 列→期间映射错位；
* 上期列（2024）被标成 2025A，与本期列挤进同一期间。

---

## 三、修法：键改成（文档, 口径）

```python
doc_header: dict[tuple[str, str], list[str]] = {}

carried_header = doc_header.get((doc_id, scope_hint or "")) or doc_header.get((doc_id, ""))
...
doc_header[(doc_id, scope_hint or "")] = hdr
```

为什么用 `scope_hint` 做第二维：它本来就是"这张表属于哪条报表"的判据
（最近前置标题 / 矩形交叠），而表头继承问的正是同一个问题 ——
两者天然一致，不需要新判据。合并表的续表拿合并表的表头，
母公司表的续表拿母公司表的表头。

## 四、效果

| | 修改前 | 修改后 |
|---|---|---|
| 全库 `needs_review` | 209 | 179（−30） |
| 事实总数 | 1048 | 1050 |
| 000722 的 2024A | 只有 p159 子公司杂项 | 有自洽三元组：资产 3,441,060,747.63 / 负债 269,554,260.75 / 权益 3,171,506,486.88 |
| 000722 的 2025A | 三项命中真值 | 三项仍命中真值（无退化） |
| 601857（目标公司）DCF | ¥14.0394 | ¥14.0394（完全一致） |
| 601857 四项事实假设 | 全事实 | 全事实（完全一致） |

−30 条复核项是本轮最实在的收益 —— 它们此前是因为期间映射错位被冲突守卫
误标的（同一张表内同一指标出现两个值），现在期间分开了，冲突自然消失。

## 五、本轮没有完全解决 000722 的 2024A —— 以及一条被否决的后续尝试

2024A 现在有数据了，但选到的是母公司口径：

| 指标 | 2024A 候选（修改后） | 真值 |
|---|---|---|
| 总资产 | 3,441,060,747.63（`parent_only`, p74） | 3,777,520,118（合并） |
| 总负债 | 269,554,260.75（`parent_only`, p75） | 394,536,433（合并） |
| 所有者权益 | 3,171,506,486.88（`parent_only`, p75） | — |

合并真值（3,777,520,117.62 / 394,536,433.28）仍在 2025A。

也就是说还差一层：p74/p76 的行被归到了 `parent_only`，而它们装的是合并表的数
（行标签 `使用权资产`/`无形资产` 与 p73 合并表连续）。这是
报表归属（口径）错标，与本轮修的表头继承是两个独立问题。

> **2026-10-10 口径订正（上表「真值」一列的标注写反了）**。按 PDF 原文
> （`fitz` 全文检索 + 逐行重建，页码 1 起）复核：
>
> * 3,777,520,117.62 与 394,536,433.28 都只出现在**物理第 76–77 页**，
>   即**母公司**资产负债表（母公司恒等式成立：394,536,433.28 +
>   3,382,983,684.34 = 3,777,520,117.62）。它们不是"合并真值"。
> * 3,441,060,747.63 与 269,554,260.75 出现在**物理第 74–75 页**，
>   即**合并**资产负债表（合并恒等式成立：269,554,260.75 +
>   3,171,506,486.88 = 3,441,060,747.63），且与物理第 9 页「主要会计数据」
>   披露的总资产 3,441,060,747.63 一致。上表把它们标成母公司口径，也是反的。
> * 所以上表读作：候选列里的 `parent_only` 其实是**合并数**（标签错），
>   「真值」列里的数是**母公司数**（当轮基准文件用了母公司口径，
>   该基准已于 2026-10-10 改正为合并口径）。
> * 本节的核心结论不受影响 ——「p74 的行被归到 `parent_only`，而它装的是
>   合并表，这是口径错标」这个判断是对的，而且现在两边证据一致。
>   本节末尾"记入 README 已知限制"的那条限制也仍然成立。
> * 但第 5.1 节末尾那条**试行修法**的历史结论要重读一遍：它比较的是
>   「2024A 有没有自洽三元组」，与口径标签正反无关，因此"净效果为负"
>   的否决仍然有效，不必重跑。

### 5.1 ★ 试过修它，被实测否决

排查发现 `scope_by_overlap` 的比较键是纵坐标，而年报里大量续表是整页高的 ——
标题必然落在表格矩形内部。实测 000722：

```
p73 标题「1、合并资产负债表」 y=74.2
p74 表格（续表）              y=[72.1, 754.6]        ← 整页高

p73 标题 → gap=-12.5  → 惩罚分支 → score 830.4
p75 标题 → gap=-386.1 → 惩罚分支 → score 456.8      ← 反而赢
```

于是 p74（合并表的续表）被配给了 p75 的母公司标题。看起来是个明确的 bug。

试的修法：整页高（`ty1-ty0 > 500`）的表，改用"文档顺序里最近的前置标题"。

实测否决（`annual38-hdrkey` vs `annual39-scope`）：

| | 修改前 | 修改后 |
|---|---|---|
| `needs_review` | 179 | 177（只少 2 条） |
| 000722 的 2024A | 有自洽三元组 | 完全没有数据 |

净效果为负。口径判对了，但那一期的期间又错了（上期列落到别处），
于是原本能凑出的三元组也消失了。

这不是一个可以单独修的问题：口径与期间两个映射在续表上互相纠缠 ——
`carry_header` 按口径键查表头，口径一变，继承到的表头就变，
期间随之改变。改任一个都会把另一个带偏。

结论：`scope_by_overlap` 保持原样，p74 归到母公司口径这件事记入
README 已知限制第 23 条，不在下游加补充判据。两条被否决的实现都留了注释。
